KAORU / 使い方

使い方

自分の端末や顧客のプロジェクトでKaoruを使うための設定、作業例、確認事項。

このページの内容インストールと初回起動プロバイダー、モデル、費用ワークスペースとルール最初の依頼の例テストと完了の確認音声、ブラウザー、OS連携とチームでの利用作業の継続と復旧顧客へ引き渡す前に

1. インストールと初回起動

ソースからのインストールにはGit、Node.js ≥ 18、npm ≥ 9が必要です。ネイティブモジュールはElectron向けに再ビルドします。OSによってはビルドツールも必要です。依存関係の導入に失敗した場合は、インストールのリファレンスを確認してください。

Git / npm 
git clone https://github.com/Dregxmoon/Kaoru-Agent.git
cd Kaoru-Agent
npm install
npm run rebuild
npx electron .

開発環境で次のコマンドを実行してください。初期設定、音声、OS固有の依存関係は、リポジトリのリファレンスを参照してください。

詳しいインストール手順 ↗RAM・CPU・ディスクの暫定要件（スペイン語） ↗公開リリースを確認 ↗

2. プロバイダー、モデル、費用

Kaoruの設定でプロバイダーとモデルを選び、利用権限のあるキーまたは互換エンドポイントを設定します。プロバイダーのデータポリシー、上限、料金を確認してください。オープンソースのソフトウェアにAPIの利用料は含まれません。ローカルモデルを使っても、TTS、ブラウジング、連携が自動でオフラインになるわけではありません。

3. ワークスペースとルール

チャットのツールバーからプロジェクトのフォルダーを選び、依存関係とルールを準備します。AGENTS.md、CLAUDE.md、.cursorrulesを取り込めます。作業と無関係なファイルは含めないでください。プロジェクトルールは作業の指針となり、実行権限は別に判定されます。

4. 最初の依頼の例

「このフォームの入力検証を調べ、関連ファイルと必要なテストを示してください。まだ編集しないでください」と依頼してみてください。その後、結果を確認できる具体的な変更を許可します。計画、操作履歴、差分を確認し、作業を止めたいときは生成をキャンセルしてください。

5. テストと完了の確認

プロジェクトの検証コマンドを設定します。smartモードでは、認識された変更後に品質チェック用スクリプトや、補助的なJavaScript構文チェックを実行できます。関連テストの自動選択はtests/run-all.shに対応し、それ以外は設定が必要です。影響範囲の推定は近似であり、結合テストの代わりにはなりません。

6. 音声、ブラウザー、OS

音声機能にはPythonとASR/TTSの設定が必要です。マイクは明示的な操作で起動し、押すとKaoruの発話を中断します。URLを開く際は既定のブラウザーを、ページを検査する作業では別プロファイルの管理対象Chromiumを使います。アクセシビリティはLinuxでAT-SPI2、WindowsでUI Automationを使用します。macOSは一部対応です。

7. 連携とチームでの利用

権限のあるアカウントだけを接続してください。GitHubとGoogleでは必要なスコープを選び、不要なアクセスを取り消します。MCPとプラグインの配布元や権限を確認してください。顧客データを使う前にテスト用リポジトリで試し、端末外に送れる文脈の範囲を合意してください。

8. 作業の継続と復旧

記憶と永続的な目標には、正常に動作するローカルストレージが必要です。重要な操作の前にバックアップを用意してください。チェックポイントは外部サービスの操作を自動で取り消しません。読み取り専用のサブエージェントは並列に調査できますが、ワークスペースを変更する処理は直列で実行します。

9. 顧客へ引き渡す前に

機能、差分、テスト、報告された制限を確認します。その環境のプロバイダー、権限、データの扱いを記録してください。商用で配布する場合は自作または適切な利用権限のあるアバターを使用します。三月なのかのアセットはMITの対象外です。このサイトは契約上のサポートやSLAを提供するものではありません。
