Open source · Personal assistant with agent capabilities

Your AI assistant
for code and desktop.

Kaoru talks with you, remembers context and stays with you through text, voice and a Live2D presence. When it is time to act, it can work as an agent: inspecting your project, preparing a plan, using tools and checking results under the permissions you configure.

01 / KAORU

More than a coding agent

Talk with Kaoru, ask it to remember what matters or delegate a multi-step task. It can help across your project and desktop; available capabilities depend on your provider, operating system and permissions.

01

Work in a repository

Explore files, dependencies and LSP symbols to inform a plan. Read and edit code, run commands and use Git. The structural index is bounded; references and file contents still need confirmation through project tools.

02

Check changes

In the smart workflow, a recognized mutation triggers configured verification. Compatible focused tests run before general checks; a skipped or failed result does not count as a passed test.

03

Resume an objective

Objectives, steps and evidence can persist in SQLite so work can continue. If storage falls back to memory, that continuity does not survive application shutdown.

04

Keep context in conversation

Local memory retrieves facts, preferences and episodes related to a conversation. You can ask Kaoru to forget memories. Retrieved context may be included in a request to your AI provider.

05

Use voice and an avatar

Vosk transcribes audio locally; Edge TTS generates speech through a Microsoft service. Pressing the microphone interrupts playback. The avatar supports configurable models and gestures.

06

Operate your desktop

Open applications and websites, inspect accessible controls and use enabled screen, pointer or keyboard capabilities. Linux and Windows support semantic controls; macOS does not yet have equivalent coverage.

07

Connect your tools

GitHub, optional Google Workspace, MCP servers and plugins expand available tasks. Each connection has its own permissions, dependencies and potential data transfers.

08

Receive timely suggestions

Configured sensors provide system and project signals. Proactivity evaluates context and policies to suggest help; it does not grant the model additional execution permissions.

09

Choose where the model runs

Configure a compatible provider or a local endpoint. Quality, cost, vision and tool availability depend on the selected model and service.

02 / KAORU

From conversation to results

Ask for guidance, continue a conversation or delegate a concrete result. When Kaoru acts as an agent, you can follow the plan and tool activity in chat; authorization and verification are part of execution.

  1. 01

    Inspect

    Examine the workspace, find relevant paths and consult available symbols.

  2. 02

    Plan

    Break the objective into steps with observable completion criteria.

  3. 03

    Authorize

    Rules allow, ask about or block actions according to their scope.

  4. 04

    Execute

    Use tools and retain their results as evidence of the work.

  5. 05

    Run checks; a failure can trigger repair or leave work pending.

03 / KAORU

Choose what Kaoru can access

Configure permissions for your task and device. The application separates model proposals from the controls that authorize tools.

Tool permissions

Allow, ask and deny rules automate specific operations, request confirmation or block them. Not every action displays a prompt: the active policy determines that.

Separate desktop capabilities

Applications, browser, screen, pointer, keyboard, processes and camera have independent controls. The current camera tool checks status or opens the camera application; it does not take photos or record video.

Isolation depends on the environment

Electron windows are isolated from direct Node access. Command isolation is a separate mechanism and depends on the system’s capabilities and configuration.

Checkpoints and recovery

Kaoru captures a baseline for recognized changes. Recovery has limits: remote actions, arbitrary commands and external effects may not be reversible.

External content

Web and integration results are treated as untrusted content in the flows that delimit them. These controls reduce the risk of malicious instructions; they do not guarantee immunity.

Data and credentials

Memory and embeddings are stored locally. Prompts may leave the device for your chosen provider. The system keychain is used when available; configuration backups require care.

04 / KAORU

Set up Kaoru for the way you work

Personal use

Start with conversation, one workspace and the permissions you need. Enable voice, memory or suggestions to suit your routine; you can change the Live2D model.

Development

Declare repository rules, prepare dependencies and configure verification commands. Review diffs and results before integrating important changes.

Teams and client projects

Define what information may reach the provider, who manages credentials and which tools are allowed. The code license does not cover characters or replace your organization’s policies.

On your desktop

Actual project screenshots. Appearance varies with your model and configuration.
