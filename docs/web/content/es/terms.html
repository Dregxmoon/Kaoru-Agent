1. Aceptación y alcance

Al instalar o usar Kaoru aceptas estos términos y el Aviso de privacidad. Si no estás de acuerdo, no uses la aplicación. Estos términos cubren el software del proyecto; los proveedores, sitios, modelos, plugins, servicios conectados y assets de terceros mantienen sus propias condiciones.

2. Qué ofrece Kaoru

Kaoru es una aplicación de escritorio de uso personal con chat, memoria, voz, proactividad y herramientas. Puede leer o modificar archivos, ejecutar comandos, usar Git/GitHub, abrir sitios, controlar interfaces accesibles, realizar clics visuales vinculados a capturas, enviar teclado, listar o detener procesos y abrir aplicaciones. La capacidad “cámara” actual consulta estado o abre la aplicación correspondiente; no graba ni toma fotografías.

open_website utiliza normalmente tu navegador predeterminado y su sesión existente, aunque Kaoru solo solicita abrir la URL. Los flujos que requieren inspeccionar DOM, buscar, hacer clic y verificar se ejecutan en un perfil Chromium administrado y separado.

3. Automatización, permisos y riesgos

Kaoru aplica reglas allow, ask y deny, aprobaciones de sesión, límites de ruta y, según la acción, checkpoints y verificación. También permite desactivar por separado aplicaciones, navegador, pantalla, puntero, teclado, procesos y cámara. Eres responsable de revisar esa configuración y las solicitudes de aprobación.

Una aprobación autoriza el intento, no garantiza la intención ni el resultado. Una coordenada puede apuntar al lugar equivocado si la pantalla cambia; un comando puede borrar datos; detener un proceso puede perder trabajo; y una acción en Google, GitHub u otro sitio puede ser difícil de revertir. Conserva respaldos y verifica las operaciones importantes.

El modo de autonomía no amplía por sí solo los permisos del sistema. Incluso en modo “Actuar”, solo deben ejecutarse automáticamente las acciones cubiertas por una regla explícita. Los mecanismos de sandbox, validación, detección de prompt injection y rollback reducen riesgos, pero no los eliminan.

4. Inteligencia artificial

Las respuestas y decisiones de herramienta pueden depender del proveedor LLM que configures. Los modelos generativos pueden equivocarse, omitir contexto, inventar información o interpretar mal una interfaz aunque el resultado parezca convincente. Verifica de forma independiente las decisiones médicas, legales, financieras, de seguridad y cualquier acción irreversible.

El catálogo de proveedores y modelos cambia con el tiempo. Tu relación con un proveedor externo se rige por sus términos, precios, límites y políticas. Un endpoint local puede evitar transferir el prompt a un proveedor remoto, pero otras funciones de red —TTS, web, GitHub o actualizaciones— seguirán conectándose si las usas.

  • No compartas archivos de configuración: si el llavero del sistema no está disponible, algunas credenciales pueden quedar en archivos locales legibles por tu usuario.
  • Los sitios visitados, Microsoft Edge TTS, proveedores LLM, GitHub, models.dev y plugins son servicios o componentes de terceros; Kaoru no controla su disponibilidad ni sus políticas.
  • Un plugin puede procesar contexto y ejecutar código con el alcance que le concedas. Revisa su origen, dependencias y permisos antes de instalarlo.
