Guía de uso

Configuración, tareas y criterios de revisión para utilizar Kaoru en tu equipo o en un proyecto de cliente. Desde v2.3, la interfaz puede seguir el idioma del sistema o usar inglés, español o japonés.

1. Instalación y primer arranque

Descarga Kaoru para tu sistema operativo. Al pulsar el botón, la descarga empieza de inmediato, sin pasar por otras páginas. Después abre el instalador y sigue la guía de primer arranque.

2. Proveedor, modelo y coste

Elige el proveedor y el modelo en la configuración de Kaoru. Usa una clave autorizada o un endpoint compatible. Revisa la política de datos, las cuotas y el coste de tu proveedor; el software abierto no incluye consumo de APIs. Un modelo local no desconecta automáticamente TTS, navegación ni integraciones.

3. Workspace y reglas

Selecciona la carpeta del proyecto desde la barra del chat. Prepara sus dependencias y reglas: Kaoru puede incorporar AGENTS.md, CLAUDE.md o .cursorrules. Evita incluir archivos ajenos a la tarea. Las reglas del proyecto orientan el trabajo; los permisos de ejecución se resuelven por separado.

4. Terminal con chat lateral

Crea una terminal en tu workspace y pulsa Chat para abrir una conversación vinculada sin detener la shell. Selecciona salida y usa Preguntar a Kaoru para adjuntarla como tarjeta; revísala antes de enviar. Explicar error prepara un borrador. Los bloques de un comando del chat permiten pegarlo sin ejecutarlo o ejecutarlo tras una confirmación explícita. La shell conserva los permisos de tu usuario.

5. Una primera tarea útil

Prueba con: “Analiza cómo se valida este formulario, identifica los archivos implicados y propón las pruebas; todavía no edites”. Después autoriza un cambio concreto con un resultado observable. Revisa el plan, la actividad y el diff, y cancela la generación si necesitas detener el trabajo.

6. Pruebas y finalización

Configura los comandos del proyecto. En smart, la verificación posterior a mutaciones reconocidas puede ejecutar scripts de calidad y un control de sintaxis JS de respaldo. La selección focal automática reconoce tests/run-all.sh; otros runners requieren configuración. Las búsquedas de impacto son aproximadas y no sustituyen las pruebas de integración.

7. Voz, navegador y sistema operativo

Para una tarea entre aplicaciones, describe los resultados que quieres observar: «abre el informe en el editor, crea un recordatorio y comprueba que aparece». Kaoru prepara y revisa una misión, pide autorización inicial y avanza resultado por resultado; si la accesibilidad no permite comprobar uno, informa el paso pendiente. La voz neuronal viene incluida y requiere internet; la entrada por micrófono no está disponible en la interfaz actual. Abrir una URL usa el navegador predeterminado; inspeccionar páginas usa Chromium administrado. Linux usa AT-SPI2 y Windows UI Automation; macOS tiene cobertura parcial.

8. Integraciones y trabajo en equipo

Conecta únicamente cuentas autorizadas. En GitHub elige los alcances necesarios y revoca accesos que ya no uses. Revisa el origen y los permisos de los plugins. Empieza con un repositorio de prueba antes de usar datos de clientes y acuerda qué contexto puede salir del equipo.

9. Continuidad y recuperación

La memoria y los objetivos durables necesitan el almacenamiento local operativo. Guarda respaldos antes de operaciones importantes. Un checkpoint no revierte automáticamente acciones en servicios externos. Los subagentes de lectura pueden investigar en paralelo; los que modifican el workspace se ejecutan de forma serial.

10. Antes de entregar a un cliente

Comprueba el resultado funcional, el diff, las pruebas y las limitaciones informadas. Documenta proveedor, permisos y tratamiento de datos para esa instalación. Si distribuyes Kaoru comercialmente, usa un avatar propio o con derechos adecuados: los assets de March 7th no están cubiertos por MIT.
